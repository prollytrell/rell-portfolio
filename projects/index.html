Professional Projects

Security Operations • Analyst Training

SentinelOne-Style SOC Training Simulator

Cybriant – 2026

An interactive investigation simulator, packaged as SCORM, that trains analysts to work an EDR alert the way a senior analyst would: gather endpoint evidence first, decide on escalation, then write a ticket the client can act on.

  • Five investigation scenarios: suspicious network activity, ransomware, registry persistence, scheduled-task persistence, and an approved deployment (a benign case that tests restraint).
  • Analysts pull command lines, publishers, hashes, mitigation status, and endpoint context before choosing what to query.
  • Includes event-search filters, disposition and escalation decisions, and ticket writing.
  • Paired with an alert-board reference covering alert types, hash reputation checks, and how much evidence a client needs to act.
Security Automation • SOAR

AI-Assisted SOAR Playbooks in Google Security Operations

Cybriant – 2026

SOAR playbooks for a SOC handling roughly 10,000 cases a month, where automation collects the evidence, Gemini summarizes it, and an analyst validates the summary before any decision is made.

  • Separate branches for curated and custom detection rules, with a fallback to raw UDM events when alert data is thin.
  • Structured JSON input and an engineered prompt so summaries are consistent and reviewable.
  • Analysts keep decision authority over severity, disposition, and response actions.
  • Evaluated on evidence quality, analyst efficiency, client ticket quality, token cost, and vendor risk.
Vulnerability Management • Automation

Reusable Automox Remediation Worklets

Cybriant – 2026

PowerShell worklets that remediate vulnerability findings and schedule reboots through Automox, built to be reused across clients rather than written one-off.

  • Workaround-first remediation where a vendor patch was not yet approved, with direct patch worklets ready once installers were provided.
  • Developed and tested in an isolated Windows VM lab before moving to a corporate test machine.
  • Reboots handled through Automox policy settings rather than inside the script, keeping remediation logic and scheduling separate.
  • Part of a wider effort to modernize vulnerability management: remediation SLAs, metrics, and Tenable–Automox integration.

GRC • Enterprise Risk Management

Healthcare Risk Management Program Using Clearwater IRM

Academic Project – 2025

End-to-end risk management engagement for a fictional healthcare system using Clearwater IRM. Our team defined asset component groups, built an enterprise asset inventory, prioritized systems based on weighted criteria, performed quantitative risk analysis, and designed governance-aligned risk responses and policy updates for a regulated clinical environment.

  • Defined logical component groups for desktops, applications, cloud backups, and clinical systems to align with Clearwater’s IRM methodology.
  • Built a structured asset inventory and weighted ranking model using criteria such as compliance impact, confidentiality, incident likelihood, data volume, and patient safety.
  • Calculated Clearwater risk ratings for high-value assets (e.g., EHR, SQL Server, Office 365, internet gateways) to identify top enterprise risks.
  • Documented detailed risk responses and “add or enhance” control actions mapped to specific threat/vulnerability pairs, including DLP, MFA, authentication policies, and secure disposal practices.
  • Co-authored an Issue-Specific Security Policy (ISSP) on fair and responsible use of information systems for the Sunshine Healthcare System, tying technical controls back to organizational mission and regulatory requirements.

Security Operations • Vulnerability Management

Vulnerability Assessment of Hidden Linux & Windows Systems

Academic Project – 2024

Conducted a structured vulnerability assessment using Nmap and Greenbone Security Manager on a concealed lab environment. The Linux server scan identified multiple critical and high-risk vulnerabilities, each mapped to detailed remediation steps.

  • Discovered exposed services, outdated software, weak encryption, and backdoored components.
